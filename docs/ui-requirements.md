# 面板 UI 需求

日期：2026-09-15
状态：已实现（含已知缺口，见 §12）

## 0. 这份文档怎么用

这是**面板 UI 的需求清单**，不是设计随笔。每个编号都可以被引用（写 PR、写 review、写 issue 时直接用编号），每条都标了**验证方式**：

- **自动** —— 有测试钉住，`npm test` 会失败
- **脚本** —— 可以脚本核对，但当前没进测试
- **人眼** —— 只能人看（渲染层没有 DOM 测试框架，见 §11）

改界面之前先读 `AGENTS.md`（设计护栏与项目约定）。视觉语言的**唯一事实来源是 `public/index.html` 的 `<style>`** —— 它零依赖移植自一份 v0 参考 UI（原文件 `ui/app/globals.css`）。这份文档管的是**需求**：必须显示什么、不许说什么、必须撑住哪些状态。

## 1. 目标与使用者

| 编号 | 需求 |
|---|---|
| G1 | 回答一个问题：**现在这 38 对的报价情况怎么样** |
| G2 | 使用场景是**运维巡检**：打开扫一眼，90% 的时间只看「有没有问题」；剩下 10% 要能下钻到某一条路由的细节 |
| G3 | 使用者是**在服务器旁边的人**：他可能正在看日志、敲 curl，面板要能替代「敲 curl 看 /latest」这件事 |
| G4 | 面板与 API **同源**，不额外部署任何东西；零依赖、离线可用 |

## 3. 数据需求（必须显示什么）

| 编号 | 要求 | 来源 | 验证 |
|---|---|---|---|
| D1 | 每对币对一行，共 38 行（白名单全量） | `/pairs` + `/latest` | 脚本 |
| D2 | 必须显示：币对、状态、付 → 得、USD、成本、较基准、可按、延迟、最后报价 | 见下 | 自动（表头 9 列） |
| D3 | **付 → 得**：金额以人类可读形式显示，用**各自** token 的小数位换算（源用 `fromDecimals`、目标用 `toDecimals`）。币对第二行显示**源链 · 目标链** | `/latest` + `/pairs` | 自动（渲染测试断言标记） |
| D4 | **成本** = `(amountInUsd − amountOutUsd) / amountInUsd`，用**美元口径** —— 不能用两个最小单位相除（小数位不同时无意义，实测会得 100110509950192%） | `/latest` | 自动 |
| D5 | **较基准** = 当前 `amountIn` 相对近 1 小时成功报价中位数的百分比，带正负号 | `/stats?window=1h` | 自动 |
| D6 | **可按**：该对能通过的最大金额档位（名义美元） | `/depth` | 自动 |
| D7 | 报价失败时**对方返回的原文**必须可见：悬停在状态徽章上可看（快捷），展开详情里有一整行（完整、且键盘/触屏可达）。**不翻译、不改写** | `/latest` | 自动（渲染测试断言两处都在） |
| D8 | 展开某行显示排障字段：`correlationId`、`minAmountOut`/`minAmountIn`、`HTTP`、`swapType`、配置金额、连续失败次数、状态起始时间、失败原文 | `/latest` + `/pairs` | 自动 |
| D9 | 若有深度数据，展开行显示 5 个档位，**每档独立成块**（不是拼成一行文本），含档位、可通/不通、成本、对方原文 | `/depth` | 自动（渲染测试断言 `class="tier"` 的块数） |
| D10 | 顶部显示三个计数：正常 / 偏离 / 失败 | `/latest` 的 `stateStatus` | 自动 |

## 4. 语义需求（不许说什么）

这一节是这份文档里最重要的部分。每一条都来自真实事故。

| 编号 | 要求 | 为什么 |
|---|---|---|
| S1 | **状态列一律取服务端的 `stateStatus`，页面绝不自己判定状态** | `priceDeviationPct` 与 `minSamples` 都不在 API 里；页面硬编码就会与告警说法不一致 —— **会骗人的监控面板比没有面板更糟** |
| S2 | 偏离值四舍五入到零时**不带负号**（显示 `0.00%`，不是 `-0.00%`） | 事故：原始值 −0.0000012% 被格式化成 `-0.00%`，使用者以为数字坏了 |
| S3 | 「较基准」与「成本」是**两个不同的量**，不许混为一谈或合并 | 事故：使用者看到「付 1501.66 → 得 1500.00」旁边写着 0%，以为漏了偏离。成本回答「现在换要付多少」，「较基准」回答「这条路由是不是在变差」 |
| S4 | 「可按」列的四种状态必须可区分：档位 = 能通过的最大档；`—` = **测过，所有档位都不通**；`?` = **本次没测它**（或还没扫描过）；整列消失 = 深度扫描已关闭 | 事故：把「没测」显示成 `—`，被读成「都做不了」—— 谎报 |
| S5 | 状态与可通性不许**只靠颜色**表达，必须有文字 | 色盲可用性；且状态徽章的文字（正常/偏离/失败）本来就是给人读的 |
| S6 | 第一轮采集还没跑完时，不许说「采集已陈旧」 | 事故：`lastRoundTs` 是内存态、启动时为空 → `/health` 回 503。那个 503 的意思是「还没开始」，说成「陈旧」会让人以为采集挂了 |
| S7 | 服务不可达时**保留上一次的数据**并标注陈旧，不清空 | 陈旧但真实的数据比空白有用，但必须明确标注 |
| S8 | 金额与百分比一律保留原始精度再加格式化，**不经过浮点**（`Intl`/`toLocaleString` 也禁用 —— 输出随 locale 变，测试会不稳） | 精度与可重复性 |

## 5. 状态需求（必须撑住的状态）

| 编号 | 状态 | 表现 | 验证 |
|---|---|---|---|
| ST1 | 加载中 | 顶栏「正在加载…」，表格空 | 自动 |
| ST2 | 第一轮采集中 | 顶栏「最后更新 … · 正在采集第一轮（约 15 秒）」，**不标黄** | 自动（`freshnessText`） |
| ST3 | 正常 | 顶栏「最后更新 N 秒前」 | 自动 |
| ST4 | 采集陈旧（服务端判定） | 顶栏标黄 +「采集已陈旧」 | 自动 |
| ST5 | 采集轮次连续失败 | 顶栏追加「采集轮次连续失败 N 次」 | 自动 |
| ST6 | 服务不可达 | 红色提示条「服务不可达（已重试 N 次）：原因」+ 保留旧数据 + 指数退避 | 人眼 |
| ST7 | 接口返回 401 | 显示令牌输入框 + 提示条说明；令牌存 localStorage，保存后重试 | 人眼 |
| ST8 | 服务在跑但库是空的 | 「服务在跑，但还没有采集到任何报价 —— 等一轮（约 1 分钟）后刷新」 | 人眼 |
| ST9 | 深度扫描关闭 | 「可按」**整列消失**（含表头），不是显示一列破折号 | 自动（`no-depth` 规则存在）+ 人眼 |
| ST10 | `/depth` 拉取失败 | 只有「可按」列显示 `?`，**主表不受影响** | 自动（`buildRows` 无 depth 的行为） |
| ST11 | 某对接口返回了不在白名单里的 pairId | 也要显示出来，备注写「未知币对」 | 自动 |

## 6. 交互需求

| 编号 | 要求 | 验证 |
|---|---|---|
| I1 | 每 30 秒自动刷新（采集是 60 秒一轮，30 秒足够） | 人眼 |
| I2 | 标签页切到后台时**暂停轮询**，切回来立即刷一次 | 人眼 |
| I3 | 失败时指数退避 30s → 60s → 120s 封顶，成功后复位 | 人眼 |
| I4 | 手动刷新按钮 | 人眼 |
| I5 | 点行展开/收起详情（再点收起） | 人眼 |
| I6 | 过滤：「仅异常」= 状态**不是** `ok`（含偏离与尚未报价）；「链」= **涉及**该链（源或目标都算）；搜索 = 对 `源 → 目标` 不区分大小写子串匹配 | 自动 |
| I7 | 过滤只重渲染，**不重新请求** | 人眼 |
| I8 | 默认排序：失败 → 偏离 → 正常 → 未知，同状态内按币对 id 字典序（手写比较，不用 `localeCompare`） | 自动 |
| I9 | 窄屏时隐藏 USD 与延迟两列（表头与单元格必须**同时**隐藏，否则错位） | 人眼 |
| I10 | 所有来自 API 的文本用 `textContent` 写入，**绝不用 `innerHTML`** | 自动（无内联处理器）+ 代码审查 |

## 10. 网络与性能需求

| 编号 | 要求 | 验证 |
|---|---|---|
| P1 | 每次刷新最多 4 个请求（`/latest`、`/stats`、`/health`、`/depth`），启动时 1 个（`/pairs`） | 脚本 |
| P2 | `/depth` 失败**不影响**主表渲染 | 自动 |
| P3 | `/health` 是 503 时仍要读它的 body（「陈旧」这件事本身就是要读的信息） | 自动 |
| P4 | 不做单币对下拉查询（38 对全量一次拉比按下钻再查更便宜） | 代码审查 |

## 11. 约束

| 编号 | 约束 |
|---|---|
| C1 | **零运行时依赖**，`package.json` 不得出现 `dependencies`/`devDependencies` |
| C2 | **无构建步骤**：原生 ES 模块 + 原生 CSS，浏览器直接加载 |
| C3 | **不外链任何资源**（无 webfont、无 CDN、无 `@import`）—— 离线/内网可用 |
| C4 | 只用 `node:http` 内置静态白名单路由服务 3 个路径（`/`、`/index.html`、`/dashboard.js`），不做通用静态服务器 |
| C5 | 用户可见文字中文，标识符英文 |
| C6 | 浏览器不 `import` `src/` 下的任何东西（后端与前端不互相依赖；两侧共用的逻辑必须各自实现或用纯函数复制） |

## 12. 已知缺口（明确未满足的需求）

| 缺口 | 影响 | 修法 |
|---|---|---|
| 渲染层只被「假 DOM」覆盖 | 生成的标记有测试了（`test/dashboard-render.test.js` 跑真实 `init()` 并断言标记），但 **CSS 是否生效、真实布局、真实点击/键盘、断网表现仍然只有人眼能验收** | 改 `public/` 后必须走 README 末尾的冒烟清单 |
| 首轮采集期间 `/health` 为 503 | 外部监控若按 `/health` 判断，重启后 15 秒内会看到「不健康」 | 属服务端设计（spec §8）。面板侧已用 ST2 化解误读 |
| `.legend` 是常驻文字，会随窄屏折行 | 小屏上占两三行 | 已用较小字号与 `line-height:1.7`；如觉得挤可考虑折叠，但不能改成 `title`（会失去可达性） |
