## 1. 目标

按一条参考录屏重构面板的**视觉语言与页面框架**：

| 维度 | 现在 | 改为 |
|---|---|---|
| 框架 | 单列居中（`max-width:1280px`） | 左栏 + 主区两栏，宽屏铺满 |
| 概览 | 4 个统计数字平铺 | KPI 卡（图标 + 小标签 + 大数字 + 说明行） |
| 徽章 | 有底色的胶囊，文字对比 4.51~5.69 | 极浅底 + 深字，对比 **6.05~8.38** |
| 字体 | 通篇等宽（含 `"JetBrains Mono"` 的规则 **9 条**，`tabular-nums` 0 处） | 正文族 + `tabular-nums` |
| 横向 | 内容 1216px，表格 1020px | 外壳上限 1600 + 表格 966 + 窄屏左栏折横条 |

**录屏素材**：小红书上一条 19.03 秒、960×720、**无音轨**的后台界面设计录屏（作者 *58UI设计工作室*，标题「后台管理系统界面设计UI交互用户体验设计」）。下面所有色值、字号、栅格数都是从抽帧里**实测**出来的，不是目测。

## 2. 依据：六屏可视对照与逐屏选择

本设计的每一个决定都来自一次「画出来看」的选择，而不是文字推演。记录如下，便于日后追溯为什么是这些值。

| 屏 | 问题 | 你选的 | 关键理由 |
|---|---|---|---|
| `layout-frame` | 左栏放什么 | **A 控件入左栏** | 我们的表是 9 列、最小 1020px，把控件挪出主区直接换来表格宽度 |
| `kpi-cards` | 概览区形态 | **A 图标 + 小标签 + 大数字 + 说明行** | 最像录屏；说明行填真实占比而不是套话 |
| `chips` | 徽章形态 | **B 极浅底 + 深字，无点** | 对比度比现在好一大截 |
| `typography` | 字体 | **A 全部改正文族 + `tabular-nums`** | 录屏的数字不像打字机 |
| `rail` | 左栏细节 | **B 链列表（计数 + 异常角标），无分组小标签** | 下拉框给不了「哪条链在坏」 |
| `width-budget` | 横向空间 | **C 两者都做 + 宽屏铺满 + 窄屏左栏折横条** | 唯一在 1440/1280/1024 三档都不横滚 |

## 3. 非目标

- **不改后端、不改 API、不改数据口径** —— 后端与所有端点零改动；链计数与占比都在前端从已取到的数据算
- 不引入依赖、构建步骤、外链资源（`AGENTS.md` C1/C2/C3 不动）
- **不新增英文界面文案** —— 保留的三处大写英文标签（`ROUTE OBSERVABILITY` / `QUOTATION HEALTH` / `API ONLINE`）不变，其余新增文字一律中文
- 不做深色主题；不放宽任何 WCAG 阈值；不用投影做层级
- **不照抄录屏的侧栏导航**（见 §11.1）

```

├─ 状态提示条（跨栏，条件渲染：服务不可达 / 空库 / 需要令牌）                        ┤
├─────────────────┬────────────────────────────────────────────────────────────┤
│ 左栏 222px      │ 主区                                                        │
│                 │  标题行：QUOTATION HEALTH / 全部路由的当前报价状态             │
│  链列表          │          …新鲜度…                                [立即刷新]   │
│  （全部 + 15 条  │                                                            │
│   链，各带计数   │  KPI 卡行：正常 / 偏离 / 失败（未报价非零时才出现）            │
│   与异常角标）   │                                                            │
│                 │  表格卡（见 §4.1）                                          │
│                 │   ├ 工具条：[搜索币对…]  (仅异常)            38 / 38 对       │
│  ─────────      │   ├ 表体：9 列，吸顶表头，定高滚动                            │
│  （令牌，条件）   │   └ 页脚：38 / 38 对                                          │
│                 │  图例                                                       │
└─────────────────┴────────────────────────────────────────────────────────────┘
```

- **控件按作用域分两处**（2026-09-17 第二次修订，见 §2）：**链列表留在左栏** —— 它是「选范围」，而 15 条带计数与异常角标的链只有竖排列表放得下；**表格作用域的控件（搜索 / 仅异常 / 显示计数）放进表格卡的工具条**。原设计把这三样也放左栏：那样左栏会挤，而表格上方反而空着。
- **状态提示条跨两栏**：它说的是整个面板的状态（服务不可达 / 库为空），不该缩在主区里
- **页脚跨两栏**：现有的数据源一行（`/pairs · /latest · …`）保持原样，只是从单列变成跨栏
- **标题行不套卡片**：它直接落在页面底色上（`--background`），只有 KPI 卡与表格卡是卡片 —— 录屏的标题块就是这样，没有卡。屏 5 的线框为了画清层次给它加了白底，那是线框的简化，不是设计
- **令牌输入框条件渲染**：只在服务端要求令牌时出现在左栏底部，平时不存在（沿用现有行为）
- 「未报价」KPI 卡**仍只在非零时出现**（沿用既有决定：避免 `0 0 0` 被读成一切正常）

### 4.1 表格卡（2026-09-17 第二次修订，取自 beUI Pro 的 Data Table）

- **工具条**：表格卡顶部一行 —— 「搜索币对」输入 + 「仅异常」胶囊 + 右侧显示计数。胶囊 `border-radius:999px`、`min-height:36px`、12px 字；**选中态用「黑底浅字」**（复用刷新按钮那对色值，**不新增颜色**）。搜索框沿用现有的 `.search-label` 外观
- **吸顶表头**：`th { position:sticky; top:0 }`，底色用**实色** `--surface-alt`（不用半透明 —— 半透明会在滚动时透出行内容）
- **定高滚动**：滚动必须发生在**表格自己的容器**里。不能靠页面级 sticky：`.table-card { overflow:hidden }`（为了圆角）会把它掐掉。高度取值见 §13
- **页脚计数**：`N / M 对` 从标题行挪到表格卡底部，对齐 beUI 的 `Showing N of M` 位置
- **保留上一轮的焦点修正**：`tbody tr[role="button"]:focus-visible { outline-offset:-2px }` —— 定高滚动让这个容器更明确地成为滚动容器，焦点框更需要收回行内

## 5. 横向预算

| 项 | 现在 | 改为 | 依据 |
|---|---|---|---|
| `.dashboard-shell` max-width | `1280px` | `1600px`，且宽屏铺满 | 录屏是应用外壳、铺满窗口，没有 `max-width` |
| 单元格内边距 | `12px 13px` | `12px 10px` | 9 列 × 2 × 3px = 省 54px |
| `table` min-width | `1020px` | `966px`；**≤1024px 视口取消下限** | 见下面的既有缺陷 |
| 左栏 + 间距 | — | `222px + 24px` | 屏 5 的量 |

**验算**（内容宽 = 视口 − 64px 内边距）：

| 视口 | 内容宽 | 减左栏 246 | 表格需要 | 余量 |
|---|---|---|---|---|
| 1440 | 1376 | 1130 | 966 | **+164** ✓ |
| 1280 | 1216 | 970 | 966 | **+4** ✓ |
| 1024 | 984 | 738 | 取消下限 | 靠丢两列 + 横滚兜底 |

**左栏折叠的断点由算术推出，不是拍的**：两栏要装得下，需 `视口 − 64 − 246 ≥ 966`，即 **`视口 ≥ 1276`**。所以断点取 **`<1280px` 时左栏折成主区上方的横向链列表**。（早先口头提的 1200 是错的：那样 1200~1280 这一段会溢出约 26px。）

**顺带修掉一个既有缺陷（不是本次引入的）**：`table { min-width:1020px }` 是硬下限，而 `.hide-medium` 只是 `display:none` —— **丢了两列，表格仍然硬撑 1020px**。所以在 1024px 视口（内容 984px）**现在就已经在横向滚动 36px**。本次一并修：在 `≤1024px` 那一档把 `min-width` 取消。

## 6. 左栏

**链列表**（真实数据，15 条链 / 38 对）：

```
全部            38
near            36   [3]
eth              6
base             4
bsc              4   [2]
sol              4
tron             4   [4]
arb … zec        2
```

- 每行三格：链名（占满）+ 币对数 + **异常角标**（涉及该链且 `stateStatus ≠ ok` 的币对数，红底 `#7f261f` on `#faeae8`）
- **币对数不等于币对总数**：一个币对跨两条链，所以各链之和是 **76 = 2 × 38**，不是 38。这里数的是「涉及该链的币对」，不是「以该链为源链的币对」
- 选中态：`#e9e9e9` 底 + 600 字重
- **排序按币对数降序**。刻意不按异常数排序 —— 那样数据一变列表就跳位
- 列表自身滚动（`max-height:340px; overflow:auto`）
- **计数是前端从已取数据算的**（`chainCounts(rows)`），不改后端
- 无分组小标签（「链 / 过滤」那两层文字去掉，屏 5 选 B）
- **「仅异常」与搜索不在左栏** —— 它们是表格作用域的控件，在 §4.1 的工具条里（2026-09-17 第二次修订）
- `<1280px` 时折成主区上方的**横向链列表**（横向滚动），左栏消失

为什么值得把下拉框换成列表：真实数据里 **near 出现在 36/38 对**（它是枢纽），而 **tron 4 对全部异常**、bsc 2 对、xlayer 1 对。这种「哪条链在坏」的信息，**下拉框必须选中之后才知道**；列表一眼就看见。

## 7. 概览 KPI 卡

**形态**：图标（16px 内联 SVG）+ 小标签（11px `--muted`）+ 大数字（700 30px `tabular-nums`）+ **说明行**（11px `--muted`）。

**说明行必须是真信息**：填「38 对中的 87%」这种真实占比，而不是「共计 31 项」那种没有信息量的话。四个状态本来就是互斥完备的划分，占比是它们唯一自然的说明。

**新纯函数 `formatSharePct(count, total)`**：

- 四舍五入到整数百分比
- **`count > 0` 而四舍五入结果为 `0%` 时，显示 `<1%`** —— 否则会把「有」显示成「0%」。这与本项目已经栽过的 `-0.00%`（四舍五入到零却带负号）是同一类事故；今天 38 对里 1/38 = 2.6% 碰不到，但币对数是 `config.json` 驱动的，会变
- `total === 0` 时四张卡都不出现（此时页面走的是既有的「空库」状态，不该显示一排 `0`）

其余：

- **仅「失败」卡的数字与图标用 `--red`** —— 颜色在这里承担「需要注意」的语义
- 卡片：`--surface` 底 + `--border` 边 + `var(--radius)` 圆角，**无投影**（沿用本项目约束）
- 图标 `aria-hidden="true"`：状态已由文字表达，图标只是冗余的视觉强化，不该被读屏重复念一遍
- 卡片右上**不画 `···` 菜单**（见 §11.2）

## 9. 排版

**核心事实**（屏 4 上演示过）：中文在 `monospace` 与 `sans-serif` 下**长得一模一样** —— 等宽字体不带 CJK 字形，中文一律回退到系统 PingFang。所以「等宽 vs 正文」这道选择题**实际只影响拉丁字母与数字**。

**改动**：删除全部 9 条含 `"JetBrains Mono"` 的规则（7 处 `font:` 简写 + 2 处 `font-family:`），统一用正文栈：

```css
font-family: Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif;
```

数字加 `font-variant-numeric: tabular-nums`。

**`.mono` 类重命名为 `.num`** —— 它不再是等宽，留着旧名字会让后来的人读错。这牵动 `public/dashboard.js`（它生成这个类名）与两个渲染测试。

| 元素 | 现在 | 改为 |
|---|---|---|
| `.eyebrow` | `600 10px` mono | `600 11px` + 字距 `.06em` |
| `.headline` | `24px / 700` | `26px / 600` + 字距 `-0.5px` |
| KPI 数字 | `700 28px` mono | `700 30px` + 字距 `-0.8px` + `tabular-nums` |
| `th` | `600 10px` mono | `600 11px` + 字距 `.04em` |
| `td` | `12px` | `12px`（**不变** —— 不拿可读性换空间） |
| `.detail-grid span` / `b` | `10px` / `12px` mono | `11px` / `12px` + `tabular-nums` |
| 链名（拉丁） | — | 13px（比表体略大，它是可点目标） |

**两条会变陈旧的规则**（现在都靠 `mono` 类选元素）：

1. `@media (max-width:480px) { .top-actions .mono { display:none } }` —— 它藏的是 **`#api-state`（「API ONLINE」那行文字）**，不是新鲜度（新鲜度本来就在 `.overview` 里）。`#api-state` 去掉 `.mono` 后这条规则会失效，应改成按 id 选：`@media (max-width:480px) { #api-state { display:none } }`（行为不变：窄屏只留状态点）
2. 同一条断点里的 `.stats strong { font-size:24px }` —— `.stats` / `.stat strong` 在 §7 换成 KPI 卡后不存在了，要改指向新类名，否则窄屏字号调整静默失效

## 11. 五处不照抄录屏，及理由

1. **侧栏导航不抄。** 录屏的侧栏是 6 组 18 项导航（Patients / Consulting room / Laboratory / Pharmacy / Money / Clinic）。我们**只有一个视图**，照抄等于造一个点了不跳转的假导航 —— 撞上本项目最高原则「面板不能骗人」。替代方案是把**真实控件**放进同一位置的左栏（§6）。
2. **卡片右上的 `···` 菜单不画。** 我们没有任何对应功能。画上去就是「点了没反应」。
3. **「未报价」不用录屏的 Void 色。** 录屏的 Void 是 `#101010` 近黑字 on `#fbfbfb` 近白底、对比 **18.39:1** —— 是整排里**最抢眼**的徽章。而「未报价」在我们这儿是「这轮没取到报价」，本该是最弱的状态。照抄会让它变成最响的，正好反了。
4. **「失败」的红是我推的。** 录屏只有琥珀 / 绿 / 蓝 / 灰四色，**没有失败语义**（那是个账单界面）。我借的是它的**做法**（极浅底 + 深字），色相仍用我们的红。
5. **中文小标签做不出录屏那个味。** `ISSUED THIS MONTH` 靠的是拉丁大写 + letter-spacing；中文只能用「小号 + 灰 + 轻字距」近似。这是照搬不了的细节，先讲明免得被当成遗漏。

## 14. 风险

| 风险 | 处理 |
|---|---|
| **改动面是本项目迄今最大的一次**：`public/index.html`（结构 + 样式）、`public/dashboard.js`（装配 + 2 个新纯函数）、3 个测试文件、4 份文档 | 分阶段实现，每阶段 `npm test` 全绿再进下一步（见 writing-plans 出的计划） |

| **id 契约与渲染测试双改**，只改一处会静默漏测 | `dashboard-dom.test.js`（静态）与 `dashboard-render.test.js`（实际生成的标记）**双向钉住**，改 id 时两条都会红 |
| `formatSharePct` 的 `<1%` 边界只有 38 对时碰不到 | 单元测试直接构造 `count=1, total=300` 这类输入，不依赖真实数据 |

| **与另一个会话在同一文件上撞车**（该会话此前改的正是 `public/index.html`） | 本设计在 `feat/` 分支上实现，不合 `main`；合并由你决定 |
| `table-scroll` 横向滚动裁掉行焦点框 | 上一轮已用 `outline-offset:-2px` 修过，收窄表格后横滚概率下降但窄屏仍会横滚 —— **保留该修正，冒烟里继续验** |
| 宽屏铺满后，超宽屏（≥1600）可能过宽 | 保留 `max-width:1600px` 上限，不做无限铺满 |
