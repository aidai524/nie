# 面板视觉刷新 设计

日期：2026-09-16
状态：待评审
前置：`docs/superpowers/specs/2026-09-15-quote-dashboard-design.md`（面板本体，已实现并合入 `main`）

## 1. 目标

在**不改信息口径、不改列、不新增依赖**的前提下，让面板更好扫读：

- 表面层次能看出来 —— 现在三个表面几乎同色（实测相邻台阶亮度比 1.0267，肉眼分辨不出）
- 9 列数字表里的数字列能竖向比较 —— 现在全部左对齐，位数不一就没法比大小
- 键盘焦点在横向滚动容器里不被裁掉 —— 现在 Tab 到首行/末行时焦点框看不见

**非目标**（本期不做）：

- 改状态口径、改列、改数据源、改后端（后端零改动）
- 引入任何依赖、构建步骤、外链资源（`AGENTS.md` C1/C2/C3 不动）
- 深色主题或主题切换（`ui-requirements.md` N3 仍是非目标，V3 仍是浅色）
- 动 WCAG 判据本身（只重新钉住色值，不放宽任何阈值）

## 2. 前置：`spectrum-ui` 的可行性结论

用户要求「用 spectrum-ui 优化界面」。**结论：不能安装，只能借做法。** 这是本 spec 的决策记录，免得后人重走一遍。

`spectrum-ui` 是一个 **shadcn registry**，不是一份可抄的 CSS：

- MCP 工具（`spectrum-ui_get_component` / `install_component`）只返回安装命令 `npx shadcn@latest add @spectrumui/<name>`，**不返回源码**
- 但 registry 清单**可直接取到源码**（实测 200）：`https://spectrumhq.in/r/registry.json` 与 `https://spectrumhq.in/r/<name>.json`，`files[].content` 是完整的 `.tsx`
- 安装产物是 `.tsx` 组件 + `lucide-react` / `motion` 依赖

读了三份源码（`market-table`、`data-table` 87KB、`stat-cards`）后的实测 DNA：

| spectrum-ui 实际做法 | 与本项目的冲突 |
|---|---|
| Tailwind `neutral-*` 灰阶，`bg-neutral-50/100`、`border-neutral-200`、`text-neutral-500/900` | 无冲突，但见 §3 |
| **`dark:` 变体 90 处** —— dark-first | **V3（浅色）** + **N3（主题切换是非目标）** |
| `shadow-[...]` **外投影** 做层级 | **V2（`box-shadow` 只允许 `inset`）**，`test/contrast.test.js` 会红 |
| `motion`（framer-motion）：`AnimatePresence` + `layout`「行滑动到新位置」 | **C1（零依赖）+ C3（不外链）** |
| `rounded-xl` / `rounded-2xl` / `rounded-full`，小片用 `rounded-[4px]`/`[5px]` | 无冲突，纯 CSS |
| 行内 **SVG sparkline**（`stroke-dasharray` 描线 + 极值圆点），并包了 `usePrefersReducedMotion` | 做法无冲突，但见 §10 |
| `tabular-nums` 等宽数字 | 无冲突 —— **本项目 V6 已经这么做了** |
| 数字列右对齐、克制的表面层次 | **无冲突，可借** ← 本 spec 的实质产出 |

**可借的只有「表格约定」**：数字列右对齐、等宽数字、克制的表面层次、行内 SVG 微图。
它的「形」能零依赖重写，它的「魂」（外投影层次 + 深色 + 动效库）撞护栏。

## 3. 为什么不能把 neutral 灰阶整份搬进来

**这一节推翻本设计早期的一版建议**（「把 spectrum-ui 的中性灰作为第二层表面」）。复诊后的理由：

`--background` 是 `#f4f5f0` = **H72 S20% 的暖绿**。spectrum-ui 的 `neutral-*` 是**冷灰**。
同一份中性灰，在它的（中性）背景上是「中性」，在本项目的暖绿背景上就是「发灰的异物」——
**它的灰阶之所以成立，是因为它的背景也是中性**。整份搬会得到一块看起来像没洗干净的表卡。

再复诊**真正坏掉的是什么**：不是色相，是**台阶间距**。现状实测：

| 台阶 | 亮度比 |
|---|---|
| 卡片 → 悬停行 | 1.0554 |
| 悬停行 → 展开行 | **1.0353** |
| 展开行 → 表头 | **1.0267** ← 分辨不出 |

所以本设计**锁死色相（H=75，与 `--background` 同族），只拉亮度台阶**。饱和度随深度小幅递增（24%→28%），
因为「越深的表面越有颜色」看起来是自然的，而现状的 19%→47% 是抖动的。

## 4. 表面台阶

本节只动**表面层次**的四个色值。全设计另有**一处**改前景色（`.stat strong` 的橄榄绿 → `--foreground`），
它同时是一条假断言的修法，放在 §9.1。除此之外不改任何色值，**一个令牌名都不改**。

| 用途 | 现状 | 新值 | 新值 HSL | 位置 |
|---|---|---|---|---|
| `--surface` 卡片 | `#fbfcf8` | **不动** | — | `:root` |
| 悬停行 / 展开的行 | `#f5f7e9` | `#f4f6f0` | H75 S24% L95.2% | `tbody tr[role="button"]:hover, tbody tr.is-expanded` |
| 展开详情所在行 | `#f1f3e9` | `#edf0e5` | H75 S26% L91.8% | `.detail-row td` |
| `--surface-alt` 表头 | `#eef0e9` | `#e7ebdc` | H75 S28% L89.2% | `:root` |

台阶亮度比变为 **1.0598 / 1.0634 / 1.0540**（现状 1.0554 / 1.0353 / 1.0267）—— 三档均匀，且每一档都远超肉眼阈值。

**对比度矩阵**（4 个表面 × 4 个真实前景，单位 %，阈值 4.5）：

| 表面 | `--muted` | dev `#856400` | `--red` | `--foreground` |
|---|---|---|---|---|
| `--surface` `#fbfcf8` | 5.46 | 5.34 | 5.90 | 17.16 |
| 悬停行 `#f4f6f0` | 5.17 | 5.05 | 5.58 | 16.24 |
| 展开行 `#edf0e5` | 4.88 | 4.76 | 5.27 | 15.32 |
| 表头 `#e7ebdc` | 4.64 | 4.53 | 5.01 | 14.58 |

**全矩阵最坏 4.53**（表头 / dev）。注意该组合**实际不出现** —— 表头只有 `--muted` 一种前景（`.deviation` 只在
`td` 里）。这 4.53 是防御性余量，不是被依赖的取值。表头的 `--muted` 从 4.90 降到 **4.64**，是本设计**唯一**变窄的余量，
仍高于 4.5。

**为什么不用更深的表头**：实测 `--muted` 在 `#e6e7e4`（L 90%）上是 4.53、再深一格就跌破 4.5。
`--muted` 是表头的唯一前景，所以这里有一道硬天花板，L 89.2% 是贴着天花板取的。

## 5. 数字列右对齐

`th`/`td` 的 **第 4/5/6/7/8 列**（USD、成本、较基准、可按、延迟）右对齐，其余（币对、状态、付 → 得、最后报价）保持左对齐。

```css
th:nth-child(4), th:nth-child(5), th:nth-child(6), th:nth-child(7), th:nth-child(8),
td:nth-child(4), td:nth-child(5), td:nth-child(6), td:nth-child(7), td:nth-child(8) { text-align:right; }
```

**为什么 `nth-child` 是安全的**：窄屏丢列（`.hide-medium`）与深度关闭丢列（`.no-depth .depth-col`）走的都是
`display:none`，**不改变 DOM 序号**，所以列隐藏后对位不会错。这正是不能用「按可见列计数」的 JS 方案的原因。
展开详情行只有一个 `colSpan=9` 的 `td`，它是 `nth-child(1)`，不受影响。

**不改 JS、不改测试。** 这是 9 列数字表里最划算的一项：现在左对齐时 `$1,501.96` 与 `$9.99` 的小数点对不齐，
竖向扫不出来。

## 6. 键盘焦点不被横向滚动裁掉（修真实缺陷）

现状规则：

```css
button:focus-visible, input:focus-visible, select:focus-visible, [role="button"]:focus-visible
  { outline:2px solid var(--foreground); outline-offset:2px; }
```

`.table-scroll { overflow-x:auto }` 使其成为**两个轴**的滚动容器（`overflow-y` 由 `visible` 计算为 `auto`），
于是**纵向也会裁**。行是 `role="button"` + `tabindex="0"`，焦点框画在行外 2px 处 —— 首行与末行（以及横向滚动时最右）的
焦点框**看不见**。这是 A11Y8「焦点可见」在真实场景下的失效，不是美化问题。

修法：只针对表格行把 offset 取负，outline 落在行的内边界，不再越出滚动容器。

```css
tbody tr[role="button"]:focus-visible { outline-offset:-2px; }
```

**考虑过并否决**：`box-shadow: inset 0 0 0 2px var(--ring)`（V2 明确允许 `inset`，`test/contrast.test.js` 不会红）。
否决理由：`box-shadow` 作用在 `display: table-row` 上跨浏览器不可靠（`border-collapse: collapse` 下尤其），
而 `outline` 是本项目**当前已在用**的机制。改 `outline-offset` 一个取值，与「换掉机制 + 换掉属性」
的风险不是一个量级 —— 前者不引入新的不确定性。

## 7. 决策记录：「较基准」不加方向箭头

spectrum-ui 的 delta 是「带符号数字 + 三角 chevron」，且**绿涨红跌**。

**本项目不采用。** 理由：在「较基准」这个口径下，**正 = 我现在比近 1 小时中位数付得更多 = 更差**。
一个绿色的上箭头会被读成「变好了」—— 这正是 `ui-requirements.md` §4 要防的那类谎报（§4 每条都来自真实事故）。
方向的语义在这里与涨跌**恰好相反**，而一个箭头不可能同时表达两者。

**保留 `+/-` 文字**（S2 已定：舍入到零时不带负号），**不加方向箭头、不加涨跌配色**。
`偏离` 的黄色仍然只由服务端的 `stateStatus` 决定，页面不自己着色。

## 8. 图例在窄屏的折行

`.legend` 是一条长句（`成本 = … · 较基准 = … · 可按 = …`），窄屏折成两三行 —— 这是
`ui-requirements.md` §12 已登记的缺口。改成三个短 `<span>` 按语义单元换行，视觉上按「术语 = 说明」成组。

**不能改成 `title`**（A11Y9 / §12 明令）：`title` 在触屏与键盘上读不到。用 span 是**加强**可达性，不是削弱。

**这一条会碰唯一一处结构断言**：`test/dashboard-dom.test.js` 里

```js
const legend = html.match(/<p class="legend">([^<]*)<\/p>/);
```

的 `[^<]*` 不允许任何子元素。要放宽为允许三个 `span`（**仍然断言「成本 / 较基准 / 可按」三个口径都在**，
只是不再要求它们是纯文本 —— 这是放宽**实现方式**，不是放宽**可达性要求**）。

## 9. 测试与文档改动清单

### 9.1 `test/contrast.test.js`

1. **白名单**：`+ #f4f6f0` `+ #edf0e5` `+ #e7ebdc`；`- #eef0e9` `- #f5f7e9` `- #f1f3e9` `- #4d5424`（见 9.2）。
   已核对这 4 个旧色值在 `public/index.html` 里**各只出现 1 次**，删干净不会漏。
2. **修一条「假通过」的断言**。现状：

   ```js
   ["统计数字 / 页面背景", token("foreground"), token("background"), 4.5],
   ```

   它断言的是 `#171917`，而 `.stat strong` **实际用的是 `#4d5424`** —— 这条断言没测它声称测的东西，
   恰好违反该文件自己写的第 1 条经验（「断言必须针对**样式里实际使用的**值，不能针对『我打算用的』值」）。

   修法（两步一起）：
   - `.stat strong` 的 `color:#4d5424` → `var(--foreground)`。那层橄榄色本来就发闷，且
     「颜色只用来表达状态」更克制 —— 三个计数里只有 `失败` 该有颜色（它保留 `var(--red)`）
   - 断言改成 `fromRule(/\.stat strong\s*\{([^}]*)\}/, "color")`，**让它真的去读规则**

   改完后这条断言的取值恰好等于 `foreground`，与第 1 条「正文 / 页面背景」重复 —— 但**保留它**：
   它现在的价值不是「再验一次那个色值」，而是「**`.stat strong` 这一条规则的 color 必须在页面背景上达 AA**」。
   将来谁给它换回一个颜色，这条就会拦下来。这正是「从规则读」的意义。

3. `.stat-none strong` 用的是 `var(--muted)`，已被第 3 条「次要文字 / 页面背景」按同一色对覆盖，**不新增断言**。

## 10. 未决（不阻塞实现）

**档位量级条**：`depthCurveFor()` 已经算出每个档位的 `costText`，可以在每个**通过**的档位块里加一条宽度 ∝ 成本的细条，
把「越大越贵」画出来（借 spectrum-ui 的 sparkline 形式，但**不做描线动画** —— 一个 30 秒刷一次的面板加动效是噪音）。

本期**不做**，理由三条：

1. **只有通过档位能画**。不通的档位没有成本，画条就等于凭空给一个不存在的值 —— 唯一诚实的画法是**留空**，
   而五个块里两三个留空，视觉上反而比现在难读
2. **不能连线**。跨档位连线必然插值，而档位之间没有定义中间值
3. **渲染层只有假 DOM**，测不到真实布局。为一个纯装饰项引入「只有人眼能验收」的东西，性价比低于 §4–§6

需要时再单开一份 spec。
